## 第三轮：训练缺陷类型分类器（方案A，CNN 迁移学习）
- 用户选定方案 A，新增：
  - `src/train_classifier.py`：ResNet18 迁移学习微调，输入 **4 通道 = RGB(3) + PatchCore 异常热力图(1)**，
    8 类（good + 7 缺陷），5 折分层交叉验证，类别不均衡加权 + label smoothing，
    训练完直接导出 ONNX 并写 `deploy/pill/classify_config.json`。
  - `classify_infer.py`：部署端推理（仅 onnxruntime），5 折模型 softmax 平均做集成，
    `predict_defect_type()` 只在 7 个缺陷类里选（排除 good），保证与 PatchCore 判定不冲突。
  - `web_app.py`：加载分类器（存在 classify_config.json 才启用），两阶段串联：
    PatchCore 判"是否缺陷" → 判为缺陷才调分类器细分类型；返回 defect_source(model/heuristic/threshold)、
    defect_zh、defect_top3、classifier_cv_acc。分类器缺失自动回退启发式。
  - 前端：缺陷类型显示来源（分类模型预测 / 启发式推测）+ 候选类型概率。
- 训练结果：**5 折 CV 平均准确率 0.8775 ± 0.0338**（0.878/0.902/0.841/0.926/0.840），
  5 个 ONNX 导出数值校验 max|Δ| < 4e-6。
- 踩坑（三个，都已修）：
  1. Windows DataLoader 多进程 worker 各自加载 torch/CUDA DLL → `WinError 1455 页面文件太小`；
     改为**单进程 + 内存预载**（预载时统一 resize 到 384）。
  2. `np.savez_compressed` 用 zip 存键名会把 Windows 反斜杠规范化成正斜杠 → KeyError；
     统一用 `_norm_key()` 归一化（存/取两侧一致），缓存数据本身是完整的、没重算。
  3. `torch.onnx.export` 时模型在 cuda 上而 dummy 输入在 cpu → "Tensor on device cuda:0 is not on
     the expected device cpu!"；导出前先 `model.cpu().eval()`。
- 训练脚本约定：good 类只用 `train/good`，**排除 `test/good`**（那是阈值标定集，避免污染）。

### 最终结果
- 5 折 CV 准确率 **0.8775 ± 0.0338**（诚实估计）
- 全测试集端到端（167 张）：缺陷检出 126/141 = 89.4%，正常误报 1/26；
  已检出缺陷的类型判定 126/126 = 100%（**乐观估计**，因每折模型见过 4/5 数据）
- 8 类端到端验证全部正确（color/combined/contamination/crack/faulty_imprint/pill_type/scratch/good）
- 耗时：缺陷 ~1.2~1.4s（PatchCore 0.7s + 分类器 0.55s），正常 ~0.7s（不触发分类器）
- 部署包新增 224MB（5 × 44.7MB ONNX + .data）；可在 classify_config.json 里减到单折
- 报告接口曾报 UnboundLocalError（`source` 在 `type_desc` 之后才赋值），已把赋值前移
- `ms` 字段改为统计完整链路，新增 `patchcore_ms` 单独给出 PatchCore 耗时
